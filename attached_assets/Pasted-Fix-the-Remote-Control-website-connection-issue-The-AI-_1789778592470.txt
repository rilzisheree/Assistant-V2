Fix the Remote Control website connection issue.

The AI Assistant Remote Control server is intended to be accessible from other devices on the local network through:

`192.168.100.17:8001`

Currently, when I open the address from Google Chrome, or scan the QR code generated by the Remote Control system, Chrome immediately redirects to the website address and shows:

`ERR_CONNECTION_REFUSED`

### IMPORTANT

Do NOT redesign the Remote Control website.

Do NOT remove or change any existing AI Assistant functionality.

Do NOT change the server architecture unless necessary to fix the connection.

### Diagnose the actual problem first

Inspect the Remote Control server code and determine:

1. What process actually hosts the Remote Control website.
2. What port it is listening on.
3. What host/interface it is bound to.
4. Whether it is incorrectly bound only to `127.0.0.1` / `localhost`.
5. Whether it needs to be bound to `0.0.0.0` so other devices on the LAN can connect.
6. Whether the QR code is generating the correct IP address and port.
7. Whether the frontend is using the correct backend/server URL.
8. Whether the server is actually running when the QR code is generated.
9. Whether Windows Firewall or another local firewall is blocking TCP port `8001`.

### Critical LAN requirement

The Remote Control website must be accessible from OTHER DEVICES on the same local network.

The server should listen on the appropriate LAN interface rather than only localhost.

If the current server framework supports it, configure the web server to listen on:

`0.0.0.0:8001`

while the QR code / browser URL should continue using the actual LAN address:

`http://192.168.100.17:8001`

Do NOT put `0.0.0.0` into the QR code or browser URL. That is the bind address, not the address users should connect to.

### QR CODE

Make sure the QR code generates exactly the reachable Remote Control URL:

`http://192.168.100.17:8001`

or the correct path if the Remote Control website uses a specific route.

Do not generate:

* `localhost`
* `127.0.0.1`
* `0.0.0.0`
* an outdated IP
* an incorrect port

The QR code should simply open the same URL that works when manually entered on another device.

### IMPORTANT NETWORK TESTING

After making the changes, verify the server from the host computer itself and then from another device on the same Wi-Fi/LAN.

Test:

`http://127.0.0.1:8001`

Then:

`http://192.168.100.17:8001`

Then test the exact same `192.168.100.17:8001` URL from a phone or another computer connected to the same network.

If localhost works but `192.168.100.17:8001` does not, investigate the server binding and firewall rather than changing the website.

### Firewall

If the application is correctly listening on `0.0.0.0:8001` but other LAN devices still cannot connect, check whether Windows Firewall is blocking inbound TCP connections to port `8001`.

Only create/modify the minimum required firewall rule.

Do NOT disable the entire Windows Firewall.

### Preserve existing functionality

Do not break:

* AI Assistant connection
* Remote Control commands
* WebSocket connections
* Authentication/security
* QR code generation
* Existing Remote Control UI
* Server API endpoints
* AI communication
* Any existing desktop application functionality

### Final requirement

The finished system should work like this:

**AI Assistant PC**
→ Remote Control server listening on `0.0.0.0:8001`

**Phone / another PC on same LAN**
→ opens `http://192.168.100.17:8001`

**QR scan**
→ opens the exact same reachable URL

**Remote Control website**
→ connects to the AI Assistant normally.

Do not just change the displayed QR URL. Fix the underlying server/network configuration so the connection actually works.
