Make the following precise UI refinements to the existing Project Zero AI Assistant interface.

IMPORTANT:

* Do NOT redesign the interface.
* Do NOT change or break any existing functionality.
* Do NOT modify backend logic, commands, APIs, assistant behavior, or event handling.
* Only make the visual, typography, sizing, animation, and interaction refinements listed below.
* Preserve the current black/dark-blue visual theme.

### 1. PROJECT: ZERO TYPOGRAPHY

The **Project: Zero** title at the top-center needs a more distinctive font.

Keep it precisely centered in the application viewport.

Change the font to something that feels:

* Futuristic
* Technical
* Clean
* Premium
* Minimal
* Slightly sci-fi
* Highly readable

The font should have a subtle futuristic/architectural character without looking like a cheesy sci-fi font.

Prefer:

* Thin to medium weight
* Slightly expanded letter spacing
* Clean geometric shapes
* Sharp but elegant typography

Keep the text relatively small.

Do NOT make it huge or overly stylized.

The final result should look like a professional AI system designation:

**Project: Zero**

### 2. COMMAND MICROPHONE / INTERRUPT AREA

The bottom command interface currently has the microphone/active and interrupt sections.

Make this area **slightly wider** so the complete text is comfortably readable.

Specifically ensure that the **Interrupt** text is never clipped, squeezed, or partially hidden.

Increase the width only enough to provide comfortable spacing.

Do NOT make the entire command bar significantly larger.

Maintain:

* Current height
* Current position
* Current visual style
* Current controls
* Current functionality

The result should feel like a small refinement rather than a redesigned command bar.

### 3. ACTIVITY LOG — SMOOTH APPEARANCE

The Activity Log windows currently appear by instantly spawning onto the screen.

This looks abrupt.

Replace the instant appearance with a smooth, polished entrance animation.

The window should feel like it is being **generated by the AI system**.

Recommended animation:

1. Start slightly smaller than its final size.
2. Begin with very low opacity.
3. Slightly blur/fade into existence.
4. Move a very small distance from the orb toward its final position.
5. Smoothly expand to 100% scale.
6. Reach full opacity.
7. Settle gently into place.

The movement should be extremely subtle.

Do NOT make it fly across the screen.

Do NOT use a dramatic bounce.

Do NOT use a generic Windows-style popup animation.

It should feel like a futuristic holographic system panel materializing.

Use a smooth easing curve such as:

* ease-out
* cubic-bezier
* smooth spring with almost no overshoot

The entire animation should be quick and elegant.

### 4. ACTIVITY LOG — DISAPPEAR ANIMATION

When the Activity Log closes, disappears, or becomes inactive, do not instantly remove it.

Give it a similarly smooth exit animation.

For example:

* Slightly reduce opacity
* Slightly shrink
* Move subtly back toward the orb
* Fade out smoothly

Keep this faster than the entrance animation.

### 5. ACTIVITY LOG — DRAGGABLE

Make the Activity Log window **movable by the user**.

The user should be able to click and drag the Activity Log window around the interface.

Important:

* Dragging should move the entire Activity Log window.
* Do not interfere with buttons, text selection, or interactive controls inside the window.
* Use the window's header/top area as the drag handle.
* The window should remain within the application boundaries.
* Do not allow it to be dragged completely off-screen.
* Preserve its current size.
* Preserve all existing Activity Log functionality.

Add a subtle cursor/interaction indication when hovering over the draggable header area so it feels intentional.

### 6. ACTIVITY LOG — REMEMBER POSITION

If practical within the existing UI architecture, remember the Activity Log's last position while the application is running.

When another Activity Log appears, it should use the user's last position rather than jumping back to the original default position.

Do not introduce unnecessary persistence complexity if the current architecture does not support it easily.

### 7. VISUAL CONSISTENCY

The Activity Log should continue using the existing:

* Black
* Dark navy
* Deep blue
* Soft white
* Subtle blue glow

visual system.

Keep the window compact.

Keep its borders and glow subtle.

Do not turn it into a giant chat window.

### FINAL FEEL

The goal is for the interface to feel **alive and physically responsive**.

The user should feel like:

They speak →
the core reacts →
the Activity Log smoothly materializes from the system →
the AI performs the action →
the Activity Log remains available and draggable →
the interface settles back into its idle state.

Nothing should abruptly appear, disappear, jump, or snap unless required for actual functionality.
